# D.one Magazine Studio

개인용 로컬 웹 앱. YouTube 자막을 가져와 로그인된 Codex CLI로 한국어 창업 매거진 초안을 작성한다. 업로드한 사진의 누끼·흑백 대비·파랑 톤·주변 사물의 선택적 주황색·인쇄 질감을 적용하고, 제목과 본문을 수정한 뒤 PNG 또는 편집 가능한 Figma 레이어로 내보낸다.

## 실행

```bash
cd /Users/jayden/Developer/done-magazine
npm start
```

브라우저에서 http://localhost:4317 을 연다. 개발 중에는 `npm run dev`, 수정 후 배포용 로컬 빌드는 `npm run build`를 실행한다. 외부 서버로 배포하지 않고 127.0.0.1에만 바인딩한다.

이 컴퓨터에는 Node, Codex CLI, ChatGPT 로그인, Python 환경과 누끼 모델을 준비해 두었다. 원고 생성은 Codex 이용 한도를 사용하며 별도 AI API 키를 요구하지 않는다. Codex가 로그아웃된 경우 터미널에서 `codex login`을 실행한다. 모델을 지정하려면 `CODEX_MODEL=모델이름 npm start`로 실행할 수 있다.

## 사용

1. YouTube 영상 URL을 입력한다. 기사 관점은 선택이며 비워두면 중심 주제를 자동으로 찾는다.
2. 표지에 사용할 JPG/PNG/WebP 사진 한 장을 올린다. 사진당 15MB 이하.
3. 매거진 초안 생성을 누른다. 본문은 사진 없이 텍스트만 생성한다. 카드 수는 내용에 따라 달라지며 표지와 D.one 엔딩을 함께 만든다. 긴 영상은 구간별 근거를 추출한 뒤 전체 원고를 구성한다.
4. 카드 목록에서 페이지를 선택하고 제목·본문을 수정한다. 사진 파일을 본문 미리보기나 하단 썸네일에 드래그해 넣는다. 원문 구절과 실제 영상 시점을 확인한다. 직접 붙여넣은 자막에 시점이 없으면 타임스탬프를 만들지 않는다.
5. 표지 후보에서 세 가지 자동 구도 중 하나를 선택한다. 후보는 같은 원고·사진의 배치 변형이다.
6. 전체 PNG ZIP 또는 Figma 편집 파일을 다운로드한다.

기존 사진에는 ‘표지 다시 디자인’을 눌러 새 스타일을 적용한다. 원고를 다시 생성하지 않는다.

각 프로젝트는 `data/projects`에 자동 저장한다. ‘프로젝트’ 버튼으로 다시 연다. 현재 프로젝트의 자동 저장은 화면에 ‘저장됨’으로 표시된다. 별도 사용자 계정이나 클라우드 저장은 없다.

## YouTube 자막

- 이 Mac에 설치된 Aside CLI의 YouTube 스킬로 타임스탬프 포함 자막을 먼저 가져온다. 브라우저 탭을 열거나 변경하지 않는다.
- Aside가 없거나 실패하면 프로젝트의 최신 로컬 yt-dlp를 보조 경로로 사용한다.
- 자막 없음, 비공개 영상, 요청 차단 등으로 두 경로 모두 실패하면 ‘자막 직접 넣기’를 사용한다. TXT/SRT/VTT/JSON3 또는 붙여넣기를 지원한다.
- 영상 파일을 다운로드하지 않으며 자막 내용만 저장한다.
- 자막과 생성 원고는 로컬에 저장되지만 원고 작성에 필요한 자막은 Codex 서비스로 전달된다. 주 피사체와 보조 사물의 위치 분석을 위해 업로드한 사진도 Codex 서비스로 전달된다. 실제 누끼와 색보정·합성은 로컬에서 처리한다.

## 표지와 템플릿

참조: `/Users/jayden/.codex/skills/done-editorial-cover/SKILL.md`, 첨부 #1~#7과 이후 제공한 선택 착색 레퍼런스. 이번 사용자 지시에 따라 스킬의 원·띠는 사용하지 않는다.

- 1080×1350, 주황 #FF660F·파랑 #1712FF, 강한 흑백 대비, 분리한 흑백 피사체, 하단 그라데이션, 종이 섬유·미세 입자의 별도 질감. 얼굴은 과도한 대비·포스터화를 피하고 중간 명암을 보존한다. 원본의 검은 배경도 선명한 파랑으로 변환한다.
- 표지 제목 Pretendard ExtraBold 90px, 본문 제목 Pretendard Bold 55px, 본문 Pretendard Regular 30px. 본문 제목의 텍스트 레이어 아래부터 본문까지 64px 간격을 유지한다. 긴 편집 문구도 글자 크기를 줄이지 않고 넘침 안내를 표시한다. 브랜드는 Playfair Display를 유지한다.
- `templates`의 파일 순서대로 본문 #2 → #3 → #4 → #5 → #6을 반복한다. #2·#6은 사진 배경형, #3은 상단 사진형, #4·#5는 하단 사진형이다. 카드 수는 내용에 따라 달라진다. 기존 프로젝트도 같은 순서를 적용한다. 마지막 페이지는 #7.jpg 원본 이미지 그대로 사용하며 텍스트 재조판이나 엔딩 편집을 하지 않는다.
- JPG 참조는 레이아웃·스타일 기준으로 사용한다. 기존 이미지에 박힌 글자를 새 원고의 텍스트로 재사용하지 않는다.
- 주황색 원·띠를 만들지 않는다. Codex가 원본 사진의 보조 사물을 최대 3개 고르고 해당 사물의 마스크에만 주황색을 입힌다. 주 피사체의 실루엣과 그 주변 경계는 착색에서 제외한다. 같은 외곽 박스 안에 있는 보조 사물도 실제 피사체 마스크를 기준으로 처리한다. 보조 사물이 없으면 임의의 도형으로 채우지 않는다.
- 사진 보정은 원본 기반 누끼와 선택 착색이다. Adobe Photoshop이나 생성형 배경 재작성 API를 호출하지 않는다. 인물의 얼굴·외모를 새로 생성하지 않는다.
- 여러 피사체, 복잡한 배경, 사진에 이미 들어간 글자는 누끼 품질이 떨어질 수 있다. 주 피사체가 뚜렷하고 텍스트가 없는 원본 사진을 권장한다.

## Figma 가져오기

앱의 ‘Figma 플러그인 다운로드’ ZIP을 풀고 Figma 데스크톱에서 Plugins → Development → Import plugin from manifest…를 선택한다. `figma-plugin/manifest.json`을 등록한다. 플러그인을 실행한 뒤 앱에서 내보낸 `.done.json` 파일을 선택한다.

제목과 본문은 네이티브 TextNode로, 사진·누끼 PNG·도형·그라데이션·질감은 별도 레이어로 생성한다. 기존 프레임을 덮어쓰지 않는다. 주황색 보조 사물은 독립적인 PNG 레이어다. 사진 자체는 래스터 이미지이고 누끼는 PNG 알파 마스크이며 벡터 누끼 경로 또는 PSD는 아니다. 웹 앱에서 사진/도형을 자유 이동하는 편집기는 제공하지 않는다.

글꼴을 Figma에서 찾지 못하면 `public/fonts/Pretendard-Regular.otf`, `Pretendard-Bold.otf`, `Pretendard-ExtraBold.otf`와 `PlayfairDisplay.ttf`를 설치하고 Figma를 다시 실행한다. SIL OFL 라이선스를 같은 폴더에 포함했다. 엔딩은 원본 템플릿 이미지 레이어이며 표지와 본문의 텍스트는 편집 가능한 텍스트 레이어다.

## 다른 컴퓨터에서 설치

Node.js 22.12 이상, Codex CLI와 로그인, uv가 필요하다.

```bash
npm install
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python 'rembg[cpu]' pillow 'yt-dlp[default]' curl-cffi
.venv/bin/python -c "from rembg import new_session; new_session('u2netp', providers=['CPUExecutionProvider'])"
npm run build
npm start
```

Aside는 선택 의존성이다. 없는 환경에서는 yt-dlp를 사용한다. `CODEX_BIN`, `YTDLP_BIN`, `ASIDE_BIN`, `PORT`로 실행 경로와 포트를 설정할 수 있다. 누끼 모델은 첫 실행 시 공식 rembg 배포에서 다운로드되고 이후 로컬 캐시를 사용한다.

## 검증

`npm test`, `npm run check`, `npm run build`. 실제 YouTube 자막 추출과 Codex 생성, 사진 처리, PNG/JSON 내보내기는 로컬 통합 검증을 별도로 수행한다. `data/verification`은 검증용 자료이고 개인 기사 원본과 구분한다.

## 근거 연결

AI는 근거의 자막 줄 번호만 선택한다. 인용문과 타임스탬프는 앱이 원문에서 직접 가져온다. 존재하지 않는 줄 번호는 최대 두 차례 자동 수정한다. 기존 생성 결과의 여러 자막 줄에 걸친 인용문은 인접 줄을 연결해 검증하되 원문에 없는 문구는 허용하지 않는다.

## macOS 데스크톱 앱

`/Applications/D.one Magazine.app`을 열거나 Dock의 D.one 아이콘을 클릭한다. 별도의 터미널 명령 없이 로컬 서버를 시작하고 macOS WebKit 창에서 스튜디오를 연다. 기존 프로젝트와 사진은 동일한 `data` 폴더를 사용한다. 사진·자막 파일 선택, PNG/JSON/플러그인 저장 대화상자, Cmd+C/V/A, Cmd+R을 지원한다. 앱 창을 닫아도 진행 중인 작업을 위해 로컬 서버는 유지한다.

앱은 이 Mac의 프로젝트 폴더·Node.js·Codex CLI에 연결되어 있다. 프로젝트를 옮긴 경우 프로젝트 루트에서 `python3 desktop/install.py`로 앱을 다시 설치한다. 설치 스크립트는 기본 macOS 개발 도구로 앱을 빌드하고 로컬 서명 후 Dock에 중복 없이 추가한다. 서버 로그는 `~/Library/Logs/D.one Magazine/server.log`에 기록한다.

상단의 ‘비우기’ 버튼은 현재 프로젝트를 저장한 뒤 URL·사진·자막·원고 등 작업 화면을 초기화한다. 저장된 프로젝트를 삭제하지 않는다.

## 사진 업로드와 배치

표지 사진은 한 장만 별도로 선택한다. 본문 사진은 한 번에 최대 16장을 선택하며 업로드 목록 순서대로 2페이지부터 배치한다. 각 업로드 버튼은 해당 사진 목록을 교체한다. 표지 사진을 본문에 섞거나 부족한 본문 사진을 자동 반복하지 않는다. 마지막 #7 페이지는 원본 템플릿을 유지한다. 본문 사진은 원본 컬러를 유지하고 노이즈 질감을 더하며 표지의 누끼·선택 착색 처리를 적용하지 않는다. 사진 가장자리의 흰 여백과 투명 여백을 제거하고 비율을 유지하여 사진 영역을 채운다. 기본 표지 구도는 실제 사진 영역을 채우는 최소 배율이며 기존 프로젝트를 열 때도 원본 여백을 계산해 적용한다.

## 본문 페이지 편집

본문 밑줄과 편집 패널의 원문 근거는 표시하지 않는다. 하단 본문 썸네일을 드래그해 순서를 바꾸며 페이지의 사진·텍스트·템플릿이 함께 이동한다. 표지와 엔딩은 고정한다. 키보드에서는 본문 썸네일에 초점을 둔 뒤 Alt+좌우 방향키로 이동할 수 있다. 맨 뒤 + 버튼은 엔딩 바로 앞에 본문 페이지를 추가한다. 추가한 페이지의 오른쪽 편집 패널에서 사진 배경형·사진 위·사진 아래 중 하나를 선택한다. 프로젝트 저장과 내보내기에 편집 결과가 반영된다.

표지 스타일에서 ‘원본 이미지’를 선택하면 원본 색상을 사용하며 흑백 누끼·파랑/주황 착색을 적용하지 않는다. 원본 모드에도 노이즈 질감과 하단 그라데이션을 적용한다. 제목과 로고는 유지한다. 원본 모드로 사진을 업로드할 때는 AI 피사체 분석을 호출하지 않는다. ‘D.one 스타일’로 다시 전환하면 필요할 때 표지 사진을 분석·보정한다. 선택한 모드는 프로젝트에 저장되고 PNG와 Figma 내보내기에 반영된다.

각 본문 페이지의 오른쪽 편집 패널에서 ‘이 페이지 사진 교체’로 한 장만 바꿀 수 있다. 표지와 본문에 좌우·상하·확대 슬라이더와 위치 초기화 버튼이 있다. 이동은 확대 후 남는 사진 영역 안에서 제한하여 빈틈이 생기지 않게 한다. 조정한 위치는 페이지와 함께 저장·이동되고 PNG와 Figma 내보내기에 반영된다.

새 초안의 본문 사진 배치는 항상 비워 둔다. 생성 후 JPG/PNG/WebP 파일 한 장을 본문 미리보기 또는 본문 썸네일에 놓으면 그 페이지에 바로 미리보기로 표시되고 업로드 후 자동 저장한다. 사진 목록의 기존 본문 사진도 드래그해 삽입할 수 있다. 사진 위·아래·배경형 템플릿의 사진 영역을 자동으로 채우며, 사진 영역에만 노이즈를 적용한다. 표지와 본문 텍스트 위에는 질감을 올리지 않는다. 엔딩은 그대로 유지한다.
